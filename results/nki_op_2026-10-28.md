## Summary

The graph break is gone: the compiled step and stats functions are one graph each (2 graphs, 0 breaks, down
from 8 graphs and 7 breaks). Products match the old path, and every batch converged in the same number of
iterations.

The speedup is real but small: **3-7% per iteration and end to end**, the same on every instance and batch
size. In absolute terms it is a near-constant **0.45-0.65 ms per iteration**, which is about the cost of the extra
graph launches and host round trips that the breaks caused. The rest of the iteration (8-17 ms here) is the
kernel itself. As nki_sell.py explains, that time is set by the number of indirect-DMA gathers, at roughly 2 us
each, and fusing the graph doesn't change it. So nki-op removes the overhead around the kernel but can't make
the kernel faster; the bigger win would still have to come from fewer gathers.

Cold compile time also drops: **by 12-18 s (about a third) on chromaticindex512-7 and neos-933966, and by 3-7 s
on neos-4300652-rahue**, probably because there are fewer graphs to compile.

Recommendation: make "nki-op" what `spmv="auto"` picks above the dense cutoff. It's faster on every row here and
falls back to "nki" by itself if registration or the first eager call fails.

Caveats: one run per cell, so differences of a few percent are near run-to-run noise. The direction is the same
in all 6 cells, though, and the absolute saving is consistent. Not yet measured: the full
`strong_branching_benchmark.py --methods neuron-nki neuron-nki-op` comparison, which also has a
`neuron-nki-op` method now.
